DFA Passport Appointment System – Redesign

IT 114: Advance Human-Computer Interaction · Laboratory Activity 3 · User-Story-Driven Redesign

Prototype

The interactive redesign will be built here in Milestone 4, based on the user stories and design patterns recorded in the Design Log.

Primary User Definition

The primary users of the DFA Passport Appointment System are Filipino citizens who go online to schedule a passport appointment and check which requirements to prepare. We focus on two groups:

User groupDescription
First-time applicant Applying for a passport for the first time. Not familiar with the steps or requirements, so they rely heavily on on-screen instructions and need clear guidance on what to do next.
Returning applicant Has used the appointment system before (e.g., for renewal). Knows the general flow but still has to read through long pages and re-enter the same personal details each time.

Decision Log

Milestone 2 and Milestone 3 decisions are recorded below in chronological order.

Entry #1 – Primary user and user stories

September 24, 2026 · Milestone 2

We interviewed three users of the DFA Passport Appointment System using the five questions in Appendix D. The users included two first-time applicants and one returning applicant. Their answers helped us understand the different problems they experienced while using the website.

Primary user decision: We defined the primary users as Filipino citizens who use the DFA website to schedule a passport appointment online. We focused on first-time and returning applicants because their experiences and needs can be different. First-time applicants mostly had difficulty understanding the process and knowing what to do next, while returning applicants were more familiar with the process but still experienced problems when completing their appointments.

Common problems we heard:

  • Too much information on the page made it harder to find important details and know what to do next.
  • Some buttons and links were not easy to notice or did not clearly look clickable.
  • Some users wanted a clearer indication of their progress during the appointment process.
  • The website did not immediately give clear feedback when incorrect or incomplete information, such as a contact number, was entered.
  • Available dates and time slots were not visually clear as selectable options, so users had to look carefully to determine which choices were available.

Result: Based on the users' answers, we created five user stories (US1–US5) focusing on progress, clear buttons and links, error handling, simple and organized information, and available appointment dates and time slots.

Entry #2 – Pattern, resource, tool, and wireframe choices

September 25, 2026 · Milestone 3

Pattern decisions: We selected the Stepper pattern for US1 because users wanted to know their current position and the remaining steps in the appointment process. We selected Inline Validation for US3 because one user experienced difficulty noticing an incorrect contact number. We selected Progressive Disclosure and Grouped Fields/Card Sectioning for US4 to reduce the amount of information presented at one time and organize related content. For US5, available appointment dates and time slots will be presented as clearly selectable cards so users can distinguish available choices more easily.

Open-source resource decisions: We evaluated Bootstrap and Bulma as UI kits, and Lucide and Font Awesome as icon libraries. We selected Bootstrap because its components fit the form, button, card, validation, and responsive-layout requirements of our user stories. We selected Lucide because its lightweight icons fit the calendar, clock, location, user, check, and warning actions needed in the redesign.

Tool decisions: We used Messenger for user communication and interviews, Figma for wireframing and annotation, Visual Studio Code for building the HTML/CSS/JavaScript prototype, and Google Chrome for testing.

Wireframe decisions: The first screen focuses on appointment date and time selection and addresses US1, US2, US4, and US5. The second screen focuses on personal information and addresses US1, US3, and US4. These screens will serve as the basis for the functional prototype in Milestone 4.

Interview Notes (Round 1 – Elicitation)

Short summaries of each interview. No names or identifying details are recorded.

User 1 – First-time applicant
  • Came to book a passport appointment and learn the requirements and steps.
  • Had to read a lot of text before finding the appointment option.
  • Unsure if some buttons were clickable; had to look around the page.
  • Wished the site showed the current step and how many steps are left.
  • Would simplify the page, reduce text, and make buttons look clickable.
User 2 – First-time applicant
  • Came to apply for a passport, book an appointment, and check requirements.
  • Wasn't always sure what to do next because of the amount of information.
  • Typed an extra digit in the contact number and the site did not flag it right away.
  • Wished the site checked entries automatically before moving on.
  • Would add clear error messages to the forms.
User 3 – Returning applicant
  • Uses the site to book an appointment and check requirements.
  • Even as a repeat user, still had to read a lot and look for buttons and links.
  • Wished the site remembered previous information and let them continue their appointment details.
  • Would reduce text, make important buttons easier to see, and show progress.
Three users were interviewed for Milestone 2: two first-time applicants and one returning applicant. No additional user is being counted in the Milestone 2 research.

Design Pattern Mapping

Each pattern is selected to address a specific user story. The patterns will be implemented functionally in the Milestone 4 prototype.

User Story Design Pattern How We Will Apply It Rationale
US1 – Progress Stepper Display Location → Date & Time → Personal Information → Review at the top of the appointment flow. Helps users understand their current position and what steps remain.
US2 – Clear controls Clear visual hierarchy / prominent buttons Use consistent primary buttons with labels such as “Continue” and “Back,” and make clickable date/time options visually distinct. Makes important actions easier to recognize and reduces uncertainty about what is clickable.
US3 – Form errors Inline Validation Validate the contact number immediately and display an error message beside the field. Allows users to correct mistakes before proceeding.
US4 – Information overload Progressive Disclosure Place detailed requirements and additional instructions inside expandable sections. Reduces unnecessary information on the main screen while keeping details available.
US4 – Organization Grouped Fields / Card Sectioning Separate appointment location, date/time, and personal information into clear sections. Makes the appointment process easier to scan and understand.
US5 – Date/time selection Grouped Fields / Card Sectioning Display available dates and time slots as clearly bordered selectable cards/buttons. Makes available choices visually obvious and easier to select.

Open-Source Resource Evaluation

We evaluated two UI kits and two icon libraries using the assignment criteria: license, quality/maintenance, and fit to our user stories. We selected one UI kit and one icon library for the prototype.

Resource Type License Quality / Maintenance Fit to Our User Stories Decision
Bootstrap UI Kit MIT Mature framework with extensive documentation and commonly used interface components. Strong fit for buttons, forms, cards, validation states, responsive layout, and navigation. Selected
Bulma UI Kit MIT Responsive CSS framework with a component-based approach. Good fit for forms, buttons, cards, and responsive layouts needed by the redesign. Not selected
Lucide Icon Library ISC Lightweight SVG icon set suitable for interface controls. Strong fit for calendar, clock, location, user, check, warning, and navigation icons. Selected
Font Awesome Icon Library Multiple licenses depending on asset Large icon ecosystem with established web integration. Good fit for common interface icons, but its licensing structure is more complicated for this student prototype. Not selected
Final resource choice: Bootstrap will be used as the primary UI kit and Lucide will be used for interface icons. These choices were made based on the resources' fit with the controls required by US1–US5 and their suitability for a self-contained browser prototype.
