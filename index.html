      Primary User Definition

      The primary users of the DFA Passport Appointment System are Filipino citizens who go online to schedule a passport appointment and check which requirements to prepare. We focus on two groups:

      User groupDescription
      First-time applicant Applying for a passport for the first time. Not familiar with the steps or requirements, so they rely heavily on on-screen instructions and need clear guidance on what to do next.
      Returning applicant Has used the appointment system before (e.g., for renewal). Knows the general steps but still has to read long pages and look around for the right buttons and links.

      Decision Log

      Entry #1 – Primary user and user stories

      September 24, 2026 · Milestone 2

      We interviewed three users of the DFA Passport Appointment System using the five questions in Appendix D. The users included two first-time applicants and one returning applicant. Their answers helped us understand the different problems they experienced while using the website.

      Primary user decision: We defined the primary users as Filipino citizens who use the DFA website to schedule a passport appointment online. We focused on first-time and returning applicants because their experiences and needs can be different. First-time applicants mostly had difficulty understanding the process and knowing what to do next, while returning applicants were more familiar with the process but still experienced problems when completing their appointments.

      Common problems we heard:

      • Too much information on the page made it harder to find important details and know what to do next.
      • Some buttons and links were not easy to notice or did not clearly look clickable.
      • Some users wanted a clearer indication of their progress during the appointment process.
      • The website did not immediately give clear feedback when incorrect or incomplete information, such as a contact number, was entered.
      • Finding a suitable available date and time could take extra effort when preferred schedules were already full.

      Result: Based on the users' answers, we created five user stories (US1–US5) focusing on progress, clear buttons and links, error handling, simple and organized information, and available appointment dates and time slots.

      Entry #2 – Pattern, resource, tool, and wireframe choices

      September 25, 2026 · Milestone 3

      Pattern decisions: We selected the Stepper pattern for US1 because users wanted to know their current position and the remaining steps in the appointment process. We selected Inline Validation for US3 because one user experienced difficulty noticing an incorrect contact number. We selected Progressive Disclosure and Grouped Fields/Card Sectioning for US4 to reduce the amount of information presented at one time and organize related content. For US5, available appointment dates and time slots will be presented as clearly selectable cards so users can distinguish available choices more easily.

      Open-source resource decisions: We evaluated Bootstrap and Bulma as UI kits, and Lucide and Font Awesome as icon libraries. We selected Bootstrap because its components fit the form, button, card, validation, and responsive-layout requirements of our user stories. We selected Lucide because its lightweight icons fit the calendar, clock, location, user, check, and warning actions needed in the redesign.

      Tool decisions: We used Messenger for user communication and interviews, Figma for wireframing and annotation, Visual Studio Code for building the HTML/CSS/JavaScript prototype, and Google Chrome for testing.

      Wireframe decisions: The first screen focuses on appointment date and time selection and addresses US1, US2, US4, and US5. The second screen focuses on personal information and addresses US1, US3, and US4. These screens will serve as the basis for the functional prototype in Milestone 4.

      Entry #3 – Building the Prototype

      September 29, 2026 · Milestone 4

      Changes while building: While building the prototype, we made some changes from our original wireframe to make the appointment process clearer and more functional. We added four main steps: Site Location, Date & Time, Personal Info, and Review. We also added a final confirmation screen after the user completes the process. The stepper now shows the current step, completed steps, and “Step X of 4” to address US1. For US2, we kept one clear primary Continue button at the bottom of each step and added a message that tells the user what is still missing before they can continue. For US4, we organized related information into separate cards and made the requirements expandable instead of showing all the details at once. We also improved the date and time selection for US5 by showing available slots, disabling fully booked options, and only showing time slots after a date is selected. A review screen with Edit buttons was also added so users can check and correct their information before confirming.

      Problems we encountered: One problem was keeping the prototype simple while still making all five user stories functional. The appointment process contains several types of information, so putting everything on one screen would make the page long and crowded. Another problem was making it clear why the user could not continue when required information was missing. We also needed a way to show form errors immediately without displaying error messages before the user had a chance to enter their information. For the date and time section, we needed to clearly separate available, selected, and fully booked options.

      How we resolved them: We divided the appointment process into separate steps and used the Stepper pattern so only the information needed for the current step is shown. We added grouped cards and Progressive Disclosure to reduce the amount of information visible at one time. Instead of simply preventing the user from continuing, the prototype displays a short message explaining what information is still required. For the personal information form, we used Inline Validation so an error appears near the field after the user interacts with it, such as when the mobile number does not contain 11 digits or does not start with 09. For appointment schedules, available dates and times are clickable, selected options are highlighted, and fully booked options are disabled. We used Bootstrap components and custom CSS/JavaScript together because Bootstrap provided useful form, button, accordion, and responsive styles, while custom code was needed for the stepper and appointment-selection behavior.

      Design Pattern Mapping

      Each pattern is linked to a user story. You can see each one working in the Prototype tab. Turn on “Show user story labels” to see which part answers which story.

      User Story Design Pattern How We Applied It Why (from the interviews)
      US1 — See my progress Stepper Four steps are shown at the top: Site Location → Date & Time → Personal Info → Review. The current step is highlighted, finished steps get a check mark, and the text “Step X of 4” is shown. Users can click a finished step to go back to it. Users said they did not know which step they were on or how many steps were left.
      US2 — Clear main button Clear primary action (visual hierarchy) Each step has only one main button (“Continue”) in a strong color, always in the same place at the bottom right. “Back” is a lighter outline button. If something is still missing, a short message next to the button says what to do. Users said some buttons and links did not look clickable, so they had to look around the page.
      US3 — Tell me right away when I make a mistake Inline Validation Each field is checked when the user leaves it, and again while they fix it. The error message shows right under the field in red (for example, “Mobile number must have 11 digits”). A correct field turns green. One user entered a wrong contact number and the website did not tell them right away.
      US4 — Short, organized requirements Grouped Fields / Card Sectioning + Progressive Disclosure Related things are put in separate cards (application type, office, requirements, name, contact). The requirements show as a short list, and the details open only when the user clicks an item. Users said there was too much text on one page, so it was hard to find what they needed.
      US5 — Clear dates and times Selectable cards + Progressive Disclosure Dates are shown as cards with the number of open slots. Full dates are grey and cannot be clicked. After the user picks a date, the times for that date appear. Users said finding an open date and time took extra effort when their preferred dates were full.

      Open-Source Resource Evaluation

      We compared two UI kits and two icon libraries on three things: license, quality/maintenance, and fit to our user stories. Versions and licenses were checked on npm/jsDelivr on September 29, 2026.

      Resource Type License Quality / Maintenance Fit to Our User Stories Decision
      Bootstrap UI Kit MIT – free to use, even for commercial work. The license notice is already inside the CDN file. Version 5.3.8. Very popular, with full documentation and many examples. Still updated. Has ready-made parts we need: red/green form states (is-invalid, invalid-feedback) for US3, cards and an accordion for US4, and strong button styles for US2. It has no stepper, so we built the US1 stepper ourselves. Includes JavaScript, so the accordion works without extra code. Selected
      Bulma UI Kit MIT – free to use, even for commercial work. Version 1.0.4. Clean, modern look and good documentation. Has cards, buttons and red/green form styles (is-danger, is-success) for US2–US4. But Bulma is CSS only (no JavaScript), so we would have to write the open/close requirements list (US4) ourselves. It also has no stepper for US1. Not selected
      Lucide Icon Library ISC – works like MIT: free to use, no credit needed on the page. Version 1.48.0. Updated often, more than 1,000 icons, all in one simple line style. Has every icon we need: map-pin (office), calendar and clock (US5), check marks in the stepper (US1), an alert icon for error messages (US3), and an arrow on the main button (US2). Selected
      Font Awesome Free Icon Library Mixed: icons are CC BY 4.0 (you must give credit), fonts are SIL OFL 1.1, code is MIT. Version 7.3.1. Very large and well known. Still updated. Has all the icons we need too. But we would have to add a credit line for the icons, and the mixed licenses are harder to follow than Lucide's single license. Not selected
      Final resource choice: We used Bootstrap as our UI kit and Lucide for icons, both loaded from the jsDelivr CDN. Bootstrap won over Bulma because it already has the form error styles (US3) and the working accordion (US4) we need. Lucide won over Font Awesome because it has one simple license with no credit required, and all the icons our stories need.

      Tool-Selection Justification

      Project ActivityToolWhy It Fits
      Finding and contacting users Messenger The people we asked were already on Messenger, so it was the fastest way to reach them and set a time. We did not need to ask for an email or phone number.
      Interviews (Round 1) Messenger voice/video call or chat A call lets us ask follow-up questions after each Appendix D question. A survey form cannot do that. Chat was a backup for users who were busy.
      Sketching / wireframing Figma Free, and both of us can edit the same file at the same time. Easy to add labeled callouts next to each screen.
      Building Visual Studio Code Free, and good for editing one file that has HTML, CSS and JavaScript together. No build step is needed, which the activity requires.
      Testing Google Chrome (with DevTools) DevTools shows JavaScript errors and lets us check how the prototype looks on a phone-size screen.
      Validating (Round 2) In person on a laptop/phone, or Messenger video call with screen sharing (planned – update after Milestone 5) The user needs to try the prototype themselves and talk out loud while doing the task (Appendix E). Screen sharing lets us watch where they get stuck.
